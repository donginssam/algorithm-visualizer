# UI와 터치 입력

## 대상 환경

주 대상은 데스크톱과 가로형 크롬북입니다. 가장 흔한 크롬북 해상도인 1366×768에서 세로 스크롤 없이 편집 화면 전체가 들어가는 것을 기준으로 합니다.

터치스크린 크롬북을 지원하므로 터치는 마우스의 보조 수단이 아닙니다. 반면 휴대폰과 태블릿 세로 모드는 현재 지원 범위가 아니며 좁은 화면 전용 탭 레이아웃도 제공하지 않습니다.

## 편집 화면 구성

```text
+------------------------------------------------------------+
| [1] TOP BAR                                                |
|     title                         examples / export        |
+------------------------+-----------------------------------+
| [2] CODE EDITOR        | [3] FLOW CANVAS                   |
|     width: 40%         |     width: 60%                    |
|                        |                                   |
+------------------------+-----------------------------------+
| [4] SYMBOL PALETTE                                         |
|     terminal / I-O / process / decision                    |
+------------------------------------------------------------+
```

1. `TOP BAR`: 왼쪽에 제목, 오른쪽에 `예제 보기`와 `이미지로 저장`을 배치합니다.
2. `CODE EDITOR`: 왼쪽 약 40%를 사용하는 의사코드 편집 영역입니다.
3. `FLOW CANVAS`: 오른쪽 약 60%를 사용하는 순서도 편집 영역입니다.
4. `SYMBOL PALETTE`: 전체 폭을 사용하는 하단 기호 팔레트입니다.

도식 안에는 폭이 일정한 ASCII 문자만 사용합니다. 한글을 ASCII 테두리 안에 넣으면 Markdown renderer와 fallback font에 따라 글자 폭이 달라져 경계선이 어긋날 수 있으므로, 실제 화면 명칭은 번호가 같은 한국어 설명에서 확인합니다.

[`src/index.css`](../src/index.css)의 `.workspace`는 `2fr 3fr` 열을 사용합니다. 상단바, 패널, 팔레트의 높이를 변경할 때 1366×768에서 body 세로 스크롤이 생기지 않는지 확인합니다.

## 입력 방식

### 의사코드

- CodeMirror에서 입력하면 300ms 뒤 파싱합니다.
- 문법 오류는 줄 밑줄과 하단 상태 영역에 함께 표시합니다.
- `<-`, `*`는 `←`, `×`로 자동 변환됩니다.
- 가상 키보드에 없는 `←`, `×`, `÷`는 기호 버튼으로 넣습니다.
- 문법 도움말은 펼쳤을 때 편집기 위에 겹쳐 표시합니다. 아래 콘텐츠를 밀면 1366×768에서 전체 높이가 넘칠 수 있습니다.
- 도움말은 바깥을 누르거나 `Esc`를 누르면 닫힙니다.

### 팔레트에서 기호 추가

[`src/components/Palette.tsx`](../src/components/Palette.tsx)는 HTML5 Drag and Drop API 대신 Pointer Events를 사용합니다. HTML5 방식은 터치에서 일관되게 동작하지 않기 때문입니다.

두 가지 방식을 모두 유지합니다.

1. 마우스나 손가락으로 기호를 캔버스까지 끌어 놓습니다.
2. 기호를 탭해 선택한 다음 캔버스의 삽입 위치를 탭합니다.

터치 이동 중에는 pointer capture를 사용하고 손끝 위치에 기호 미리보기를 표시합니다.

### 노드와 엣지 편집

- 노드는 드래그하여 옮깁니다.
- 연결점을 이어 화살표를 만듭니다.
- 노드는 더블클릭·더블탭 또는 선택 후 `편집` 버튼으로 수정합니다.
- 노드와 엣지를 선택하면 항상 보이는 삭제 버튼이 나타납니다.
- 편집 대화상자의 입력 글자 크기는 16px 이상으로 유지해 모바일 계열 브라우저의 자동 확대를 막습니다.

호버나 더블클릭에만 의존하는 기능을 만들지 않습니다. 같은 작업을 선택 후 버튼으로도 수행할 수 있어야 합니다.

## 캔버스 제스처

- 한 손가락 드래그: 노드 또는 캔버스 이동
- 두 손가락 핀치: 확대·축소
- 마우스 휠·트랙패드: 확대·축소와 이동
- 자동 화면 맞춤: 그래프 전체를 보이되 배율 1보다 크게 확대하지 않음

캔버스는 `touch-action: none`, body는 `overscroll-behavior: none`을 사용해 브라우저 스크롤·당겨서 새로고침과 캔버스 조작의 충돌을 줄입니다.

## 화면 맞추기

React Flow의 기본 `fitView`만 사용하면 감춰진 캔버스가 다시 나타날 때 DOM 크기 측정이 어긋날 수 있습니다. `FlowCanvas`는 다음 방식으로 viewport를 맞춥니다.

1. `ResizeObserver`로 캔버스 크기가 0에서 양수로 바뀌는 시점을 감지합니다.
2. `graphBounds`로 노드와 우회 화살표를 모두 포함한 실제 범위를 구합니다.
3. canvas 크기, padding, 최소·최대 zoom을 이용해 viewport를 계산합니다.
4. React Flow가 반영할 때까지 animation frame에서 확인합니다.

예제 화면은 편집 화면을 unmount하지 않으므로 다시 돌아왔을 때도 이 크기 변화 처리가 필요합니다.

## 터치 타깃과 접근성

- 공통 최소 조작 크기는 CSS 변수 `--touch-min: 44px`입니다.
- 버튼, 팔레트 항목, 기호 입력 버튼, 선택 툴바에 최소 크기를 적용합니다.
- 연결점은 보이는 Handle을 키우지 않고 가상 요소로 터치 영역만 44px까지 확장합니다.
- 키보드 사용자를 위해 전역 `:focus-visible` 링을 유지합니다.
- 아이콘이나 모양만 있는 요소에는 `aria-label`을 제공합니다.
- 팔레트에는 모양과 함께 `단말`, `입출력`, `처리`, `판단` 이름을 표시합니다.
- 순서도 기호 안 텍스트는 검정색 계열이며 대부분 16px, 판단 기호는 공간상 15px를 사용합니다.

## 디자인 토큰

색, 간격, 모서리, 그림자, 터치 최소 크기는 [`src/index.css`](../src/index.css)의 `:root`에 정의합니다. 새 컴포넌트는 가능한 한 기존 토큰을 사용합니다.

순서도 교육 표기와 연결된 다음 기호 색은 임의로 바꾸지 않습니다.

| 기호 | 변수 | 값 |
| --- | --- | --- |
| 시작·끝 | `--symbol-terminal` | `#FFE066` |
| 입력·출력 | `--symbol-io` | `#FFB3C6` |
| 처리 | `--symbol-process` | `#A8D8FF` |
| 판단 | `--symbol-decision` | `#B7E4C7` |

색을 바꿔야 한다면 화면 노드, 팔레트, PNG 생성기가 모두 같은 결과를 내는지 확인합니다.

## 수동 터치 점검표

실제 터치 크롬북에서는 다음 항목을 확인해야 합니다.

- 두 손가락 핀치로 자연스럽게 확대·축소되는가
- 한 손가락으로 빈 캔버스와 노드를 각각 이동할 수 있는가
- 팔레트 드래그와 탭하여 추가가 모두 동작하는가
- 노드 더블탭과 선택 후 편집 버튼이 모두 동작하는가
- 연결점을 손가락으로 선택하고 이을 수 있는가
- 화면 키보드가 올라왔을 때 편집 영역과 대화상자 버튼이 가려지지 않는가
- 브라우저 당겨서 새로고침이나 페이지 확대와 충돌하지 않는가

1366×768과 1440×900 브라우저 viewport 검증은 완료했지만, 실제 터치 크롬북 실기기 점검은 아직 남아 있습니다.
