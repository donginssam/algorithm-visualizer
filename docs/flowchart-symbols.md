# 순서도 기호 규칙

이 문서는 화면 팔레트, 순서도 캔버스, 자동 배치, PNG 저장이 따라야 하는 순서도 기호의 기준입니다. 기호의 의미와 모양은 교육 표기를 우선하며, 구현 상수는 이 규칙과 일치해야 합니다.

## 기본 기호

| 의미 | 그래프 `kind` | 모양 | 채우기 색 | CSS 변수 | 기준 크기 |
| --- | --- | --- | --- | --- | --- |
| 시작·끝 | `terminal` | 둥근 사각형 | 노란색 `#FFE066` | `--symbol-terminal` | 172×64px |
| 입력 | `input` | 평행사변형 | 분홍색 `#FFB3C6` | `--symbol-io` | 190×76px |
| 출력 | `output` | 평행사변형 | 분홍색 `#FFB3C6` | `--symbol-io` | 190×76px |
| 대입·계산 | `process` | 직사각형 | 연한 파란색 `#A8D8FF` | `--symbol-process` | 190×72px |
| 조건·반복 판단 | `decision` | 마름모 | 연한 초록색 `#B7E4C7` | `--symbol-decision` | 220×124px |
| 조건 분기 합류 | `junction` | 작은 원 | 흰색 | 해당 없음 | 18×18px |

`junction`은 조건의 두 흐름을 구조적으로 합치기 위한 내부 기호입니다. 팔레트에서 직접 추가하는 교육용 기호가 아니며 AST에도 별도 문장으로 나타나지 않습니다.

기준 크기는 [`src/core/astToFlow.ts`](../src/core/astToFlow.ts)의 `NODE_SIZES`에 정의되어 있습니다. 화면 CSS의 실제 크기와 반드시 같아야 하며, 한쪽만 바꾸면 자동 배치와 화살표 끝점이 어긋납니다.

### 규칙을 고정한 이유

- 의미마다 모양과 색을 함께 사용해 색을 구분하기 어려운 사용자도 기호를 식별할 수 있게 합니다.
- 시작과 끝은 같은 의미 범주이므로 같은 단말 모양을 사용하고 라벨로 역할을 구분합니다.
- 입력과 출력도 데이터가 시스템 경계를 오가는 같은 범주이므로 평행사변형 하나를 공유합니다.
- 판단은 교육 표준의 마름모를 사용합니다. 비슷해 보이는 육각형은 준비 기호이므로 대체할 수 없습니다.
- 색과 치수를 화면·팔레트·PNG에서 고정해 학생이 보는 표현과 제출 결과가 달라지지 않게 합니다.

## 기호별 의미와 연결

### 시작·끝

- 시작과 끝은 같은 둥근 사각형을 사용하고 `terminalRole`의 `start`, `end`로 구분합니다.
- 시작 기호에는 들어오는 화살표가 없고 나가는 화살표가 하나 있어야 합니다.
- 끝 기호에는 들어오는 화살표가 하나 있고 나가는 화살표가 없어야 합니다.
- 빈 프로그램은 예외적으로 시작 기호 하나와 화살표 없는 상태를 허용합니다.
- 본문이 생긴 뒤에는 끝 기호가 반드시 필요합니다.

### 입력·출력

- 입력과 출력은 같은 평행사변형을 사용합니다.
- 입력 라벨의 표준 형식은 `입력: 변수`입니다.
- 출력 라벨의 표준 형식은 `출력: 식`입니다.
- 그래프 역변환에서는 `변수 입력`, `식 출력` 형식도 읽을 수 있습니다.

### 처리

- 변수 대입과 계산은 직사각형을 사용합니다.
- 라벨은 `변수 ← 식` 형식이어야 합니다.
- `←` 앞의 변수나 뒤의 식이 비어 있으면 AST로 변환하지 않고 수정 방법을 안내합니다.

### 판단

- 조건 분기와 반복은 모두 마름모를 사용하고 `controlKind`의 `if`, `loop`로 구분합니다.
- 판단 기호로 육각형을 사용하지 않습니다. 육각형은 순서도에서 준비 표시에 해당합니다.
- 조건 분기에는 `예`와 `아니오` 화살표가 하나씩 필요합니다.
- 반복의 `예` 흐름은 반복 본문을 지나 같은 판단 기호로 되돌아가고, `아니오` 흐름은 다음 문장으로 진행합니다.

## 도형 좌표와 렌더링

비스듬한 변이 있는 평행사변형과 마름모는 CSS `clip-path`가 아니라 SVG `polygon`으로 그립니다. `clip-path`는 테두리 상자까지 잘라 비스듬한 변의 윤곽선이 사라질 수 있습니다.

캔버스와 PNG에서 사용하는 정규화된 좌표는 다음과 같습니다.

```text
평행사변형: 14,0  100,0  86,100  0,100
마름모:     50,0  100,50 50,100  0,50
```

팔레트는 76×42 viewBox 안에서 같은 형태를 축소해 그립니다. 도형 규칙을 바꿀 때는 다음 세 표현을 함께 확인합니다.

- 팔레트: [`src/components/Palette.tsx`](../src/components/Palette.tsx)
- 캔버스: [`src/components/nodes/FlowNodes.tsx`](../src/components/nodes/FlowNodes.tsx)
- PNG: [`src/core/flowToSvg.ts`](../src/core/flowToSvg.ts)

## 텍스트 규칙

- 기호 안 글자는 `--symbol-ink`인 `#111827`을 사용합니다.
- 가독성 기준은 16px 이상입니다.
- 가운데 정렬하고 긴 문장은 기호 안에서 줄바꿈합니다.
- 현재 일반 기호는 16px, 판단 기호는 제한된 내부 폭 때문에 15px를 사용합니다. 판단 글자 크기는 가독성 기준의 예외이므로 향후 16px로 맞출 때 `decision` 크기, `NODE_SIZES`, 자동 배치와 PNG 글자 크기를 함께 조정해야 합니다.

## 화살표 규칙

### 일반 흐름

- 화살표는 실선과 닫힌 화살촉을 사용합니다.
- 일반 선 색은 `#475569`, 기준 굵기는 2.2px입니다.
- 위에서 아래로 흐르며 기호 사이의 빈 공간에서 직각으로 꺾습니다.
- 다른 기호를 통과하지 않도록 `routePoints`를 계산합니다.

### 반복 복귀선

- 반복 복귀선의 `branch`는 `loop-back`입니다.
- 일반 흐름과 구분하기 위해 보라색 `#7C5CF0`을 사용합니다.
- 화면의 다른 기호를 가로지르지 않도록 그래프 오른쪽의 전용 lane으로 우회합니다.
- 중첩 반복은 서로 다른 lane을 사용합니다.

### 판단의 예·아니오

- `예`와 `아니오` 라벨을 화살표에 표시합니다.
- 두 화살표는 마름모의 서로 반대쪽인 왼쪽·오른쪽 꼭짓점에서 출발합니다.
- 두 화살표를 마름모의 아래쪽 한 점에서 출발시키지 않습니다. 선이 겹치고 도형 밖에서 시작하는 것처럼 보일 수 있습니다.
- 자동 배치 후 `decisionSides`가 목적지 위치를 비교하여 다음 기호가 놓인 쪽을 `예`로 선택하고 반대쪽을 `아니오`로 정합니다.
- 목적지 열을 구분할 수 없을 때 기본값은 조건 분기 `예=왼쪽`, 반복 `예=오른쪽`입니다.

`yesSide`는 자동 배치, 화면 Handle, 경로 계산, PNG 출력에서 같은 값을 사용해야 합니다. 상세 알고리즘은 [순서도 변환과 렌더링](./flowchart.md#판단-기호의-좌우-방향)을 참고합니다.

## 연결점과 터치 영역

- React Flow `Handle` 자체는 16×16px로 유지합니다.
- 실제 터치 영역은 `::before`를 이용해 44×44px로 확장합니다.
- Handle 상자를 44px로 키우면 React Flow가 화살표 끝을 커진 상자 바깥에 붙여 기호 사이의 선이 지나치게 짧아집니다.
- 연결점의 시각 크기와 터치 영역을 분리하는 현재 방식을 유지합니다.
