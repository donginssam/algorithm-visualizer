# 3단계 — 의사코드 파서

> 상태: 완료

## 목표

학생이 입력한 들여쓰기 기반 의사코드를 `Program` AST로 변환하고 문법 오류가 있으면 해당 줄과 고치는 방법을 안내합니다.

## 구현 내용

### 줄 단위 재귀 하강 파서

[`src/core/parser.ts`](../../src/core/parser.ts)에 공백 2칸 들여쓰기를 사용하는 파서를 구현했습니다.

- 첫 줄의 `시작`을 확인합니다.
- 본문이 있으면 마지막 줄의 `끝`을 확인합니다.
- 현재 들여쓰기 깊이를 기준으로 `parseBlock`을 재귀 호출합니다.
- 대입, 입력, 출력 문장을 구분합니다.
- `[조건 반복]` 뒤의 한 단계 깊은 블록을 반복 본문으로 만듭니다.
- `[만약 조건]`과 선택적인 `[아니면]` 블록을 조건 AST로 만듭니다.
- 빈 줄은 무시하고 탭 들여쓰기는 오류로 안내합니다.

### 입력 기호 정규화

키보드에서 입력하기 쉬운 문자를 교과서 기호로 바꿉니다.

- `<-` → `←`
- `*` → `×`

파서가 직접 정규화하므로 CodeMirror가 아닌 경로에서 호출해도 같은 결과를 얻습니다.

### 오류 정보

`PseudocodeParseError`에 다음 정보를 포함했습니다.

- 원본 줄 번호
- 오류 열
- 학생이 다음 행동을 알 수 있는 한국어 메시지

예를 들어 대입식의 오른쪽이 비어 있으면 `← 뒤에 저장할 값이나 계산식이 필요해요.`라고 안내합니다.

### CodeMirror 연결

[`src/components/CodeEditor.tsx`](../../src/components/CodeEditor.tsx)에 CodeMirror 6를 연결했습니다.

- 줄 번호, 현재 줄 강조, 줄바꿈과 history를 제공합니다.
- 오류 줄에 diagnostic을 표시합니다.
- 기호 정규화 후 커서 위치를 다시 계산합니다.
- `←`, `×`, `÷` 입력 버튼을 제공합니다.
- [`src/App.tsx`](../../src/App.tsx)에서 입력을 300ms 디바운스한 뒤 파싱합니다.

## 선택 이유와 고려한 대안

### 줄 단위 재귀 하강 방식을 택한 이유

현재 문법은 문장 종류가 적고 블록 경계가 들여쓰기로 결정됩니다. parser generator나 완전한 token grammar를 도입하면 표현력이 늘지만 학생용 오류 메시지를 문장별로 제어하기 어렵고 유지할 문법 계층이 커집니다. 줄 번호와 들여쓰기 깊이를 가진 단순 자료구조를 만든 뒤 `parseBlock`을 재귀 호출하면 중첩 구조를 AST와 거의 같은 모양으로 읽을 수 있습니다.

식 내부를 해석하지 않기 때문에 일반적인 expression parser도 필요하지 않습니다. 지원 문장이 늘어나거나 조건을 실행해야 할 때는 이 선택을 다시 검토해야 합니다.

### 공백 2칸 들여쓰기를 사용한 이유

`반복 끝`, `조건 끝` 같은 종료 keyword를 추가하는 방식보다 Python과 비슷한 들여쓰기가 블록 범위를 시각적으로 보여 줍니다. 4칸보다 2칸을 선택해 좁은 편집기에서도 중첩된 문장이 지나치게 오른쪽으로 밀리지 않게 했습니다. 탭은 화면·설정마다 폭이 달라지므로 허용하지 않습니다.

### 기호를 파서와 편집기 양쪽에서 정규화한 이유

CodeMirror에서만 `<-`와 `*`를 바꾸면 테스트나 다른 입력 경로에서 파서를 직접 호출할 때 결과가 달라집니다. 파서를 최종 방어선으로 두고 편집기는 입력 즉시 학생에게 교과서 기호를 보여 주기 위해 같은 정규화를 적용합니다.

### 300ms 디바운스를 둔 이유

매 key 입력마다 파싱하고 그래프를 다시 배치하면 아직 완성되지 않은 한 글자 상태에서 오류와 순서도가 계속 흔들립니다. 반대로 명시적인 변환 버튼은 두 표현이 즉시 연결된다는 학습 경험을 약화합니다. 300ms는 입력 흐름을 크게 방해하지 않으면서 불필요한 재배치를 줄이기 위한 절충입니다.

### 마지막 유효 AST를 유지하는 이유

문법 오류가 생길 때 순서도를 빈 화면으로 지우면 학생은 기존 결과를 잃었다고 느낄 수 있습니다. 편집 초안과 마지막 유효 AST를 분리해 오류가 있는 동안 기존 순서도를 유지하고 수정이 끝났을 때만 새 AST로 교체합니다.

### CodeMirror를 사용한 이유

일반 `textarea`로도 문자열 입력은 가능하지만 줄 단위 diagnostic, gutter, selection 보존, history와 키 binding을 직접 구현해야 합니다. CodeMirror는 필요한 편집 기반을 제공하면서 자동 기호 변환과 한국어 오류 표시를 extension으로 붙일 수 있었습니다.

## 완료 기준

- 지원하는 모든 의사코드 구문을 AST로 변환할 수 있습니다.
- 반복과 조건을 중첩할 수 있습니다.
- 공백 2칸 들여쓰기 위반과 탭 입력을 정확한 줄에서 안내합니다.
- `<-`, `*`가 교과서 기호로 바뀝니다.
- 잘못된 초안이 마지막으로 유효한 AST를 덮지 않습니다.
- 의사코드 입력 후 순서도가 실시간에 가깝게 갱신됩니다.

## 다음 단계로 전달한 규칙

- 파서는 편의를 위한 여러 입력 형식을 허용할 수 있습니다.
- AST에서 다시 생성할 때는 하나의 표준 형식을 사용합니다.
- 오류 메시지는 parser 내부 용어보다 해결 방법을 설명합니다.
- 조건과 식은 해석하지 않고 문자열 그대로 보존합니다.
