# 2단계 — AST에서 순서도 생성

> 상태: 완료

## 목표

1단계의 `Program` AST를 교육 표기에 맞는 순서도 노드와 화살표로 변환하고 화면에서 읽기 쉬운 위치에 자동 배치합니다.

## 구현 내용

### 커스텀 순서도 노드

React Flow 커스텀 노드로 다음 기호를 구현했습니다.

- 단말: 시작·끝을 나타내는 노란색 둥근 사각형
- 입출력: 입력·출력을 나타내는 분홍색 평행사변형
- 처리: 대입·계산을 나타내는 연한 파란색 직사각형
- 판단: 반복·조건을 나타내는 연한 초록색 마름모
- 합류점: 조건 분기의 두 흐름을 합치는 내부 원형 노드

현재 기호의 정확한 색과 크기는 [순서도 기호 규칙](../flowchart-symbols.md)을 기준으로 합니다.

### AST → 그래프 변환

[`src/core/astToFlow.ts`](../../src/core/astToFlow.ts)의 `astToFlow`가 AST를 React Flow 노드와 엣지로 변환합니다.

- 일반 문장은 앞뒤 노드를 `next` 엣지로 연결합니다.
- 반복은 판단 노드의 `예` 흐름에 본문을 연결하고 본문 끝에서 판단으로 `loop-back`합니다.
- 판단의 `아니오` 흐름은 반복 다음 문장으로 진행합니다.
- 조건 분기는 `예`와 `아니오` 본문을 만든 뒤 내부 합류점에서 다시 만납니다.
- `[아니면]` 본문이 없으면 `아니오` 화살표가 합류점으로 직접 연결됩니다.

### 자동 배치

dagre를 사용해 위→아래 방향으로 노드를 배치했습니다.

- 노드 종류별 실제 크기를 `NODE_SIZES`에 전달합니다.
- 일반 흐름은 dagre의 순위 계산에 포함합니다.
- 반복 복귀선은 순위 계산에서 제외하고 별도 우회 경로를 만듭니다.
- 같은 입력으로 항상 같은 위치를 얻도록 dagre 동적 cache를 사용하지 않습니다.

### 화살표 경로

- 일반 화살표는 기호 사이에서 직각으로 꺾습니다.
- 분기선은 목적지 방향으로 먼저 이동해 다른 기호와 겹침을 줄입니다.
- 반복 복귀선은 전체 그래프 왼쪽의 전용 lane으로 우회합니다.
- 조건의 빈 갈래는 그래프 바깥 통로를 사용해 다음 기호를 가로지르지 않습니다.

현재의 `예/아니오` 좌우 꼭짓점 배치와 공용 경로 계산은 6단계에서 추가로 보완됐습니다.

## 선택 이유와 고려한 대안

### React Flow를 사용한 이유

SVG나 canvas 위에 노드 이동, 선택, 확대·축소, 연결 편집을 모두 직접 만들 수도 있습니다. 그러나 터치 gesture, 좌표 변환, selection, edge interaction까지 직접 구현하면 알고리즘 변환보다 편집기 기반 기능에 더 많은 복잡도가 생깁니다. React Flow는 커스텀 기호를 허용하면서 이동·연결·viewport 기능을 제공하므로 교육 표기를 유지하고 편집 기능을 빠르게 만들 수 있었습니다.

React Flow의 기본 도형과 화살표 모양을 그대로 사용하지 않은 이유는 교육 기호, 직각 경로, 반복 우회선과 터치 연결점 규칙을 만족하지 못하기 때문입니다. 편집 기반은 재사용하고 노드·엣지 표현은 직접 구현했습니다.

### dagre를 선택한 이유

문장 수에 따라 y좌표를 단순히 증가시키는 수동 배치는 직선 흐름에는 충분하지만 조건 분기와 중첩 반복에서 열 간격과 합류 위치를 계산하기 어렵습니다. dagre는 노드 크기와 그래프 연결을 받아 위→아래 계층 배치를 만들 수 있고, 현재 규모에서는 elkjs보다 설정과 bundle 부담이 작습니다.

dagre가 모든 화살표를 교육용 순서도에 맞게 routing해 주는 것은 아니므로 노드 위치만 맡기고 실제 `routePoints`는 애플리케이션에서 계산합니다.

### 조건 분기에 합류점을 둔 이유

AST의 `if` 다음 문장을 복원하려면 `예`와 `아니오` 흐름이 끝나는 위치를 명확히 알아야 합니다. 두 branch가 임의의 다음 노드에서 암묵적으로 만난다고 가정하면 중첩 조건에서 어느 판단의 합류인지 구분하기 어렵습니다. 작은 `junction`을 내부 노드로 두어 그래프 구조를 명시하고 AST로 되돌릴 때는 제거합니다.

### 반복 복귀선을 별도로 배치한 이유

복귀선을 dagre의 일반 edge로 넣으면 판단 노드와 본문 사이의 순위가 순환 구조 때문에 불안정해질 수 있습니다. 복귀선을 layout 입력에서 제외하고 왼쪽 전용 lane으로 routing하면 본문은 자연스럽게 위→아래로 배치되고 반복 범위도 시각적으로 구분됩니다.

### 노드 크기를 변환 코드에도 둔 이유

dagre와 화살표 경로는 DOM이 그려지기 전에도 노드 경계를 알아야 합니다. CSS만 기준으로 삼으면 초기 변환과 PNG 저장에서 실제 크기를 알 수 없습니다. 그래서 `NODE_SIZES`를 계산 기준으로 두되, CSS 치수와 수동으로 동기화하는 제약을 문서와 테스트로 관리합니다.

## 완료 기준

- 예제 AST를 순서도로 표시할 수 있습니다.
- 대입, 입력, 출력이 올바른 기호로 변환됩니다.
- 반복은 본문을 지나 판단으로 돌아옵니다.
- 조건의 두 흐름은 분리됐다가 합류합니다.
- 노드가 위→아래로 자동 배치되고 일반 흐름과 반복선이 구분됩니다.

## 다음 단계로 전달한 규칙

- 화면 그래프는 AST에서 언제든 다시 만들 수 있어야 합니다.
- 노드 CSS 크기와 `NODE_SIZES`는 같은 값을 유지합니다.
- 반복과 조건은 동일한 판단 기호를 사용하되 `controlKind`로 구분합니다.
- 합류점은 그래프 내부 구조이며 AST 문장이 아닙니다.
