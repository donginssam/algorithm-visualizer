# 6단계 — 교육용 마무리

> 상태: 완료

## 목표

완성된 양방향 변환 기능을 실제 수업 환경에서 쓰기 쉬운 화면으로 정리하고, 크롬북·터치 조작·PNG 제출 과정에서 발견된 시각적 문제를 해결합니다.

## 구현 내용

### 화면 디자인과 레이아웃

[`src/index.css`](../../src/index.css)에 디자인 token을 정의하고 화면을 밝은 학습 도구 분위기로 정리했습니다.

- 표면, 테두리, 글자, accent, 상태색을 CSS custom properties로 관리합니다.
- 간격, 모서리, 그림자, focus ring과 `--touch-min`을 공통 token으로 관리합니다.
- 1366×768에서 상단바, 편집 패널, 캔버스와 팔레트가 세로 스크롤 없이 들어가도록 높이와 여백을 조정했습니다.
- 의사코드 약 40%, 순서도 약 60%의 2열 구성을 유지했습니다.
- 휴대폰과 태블릿 세로용 별도 레이아웃은 만들지 않았습니다.

### 터치와 접근성 보완

- 주요 버튼과 조작 영역을 최소 44×44px로 유지했습니다.
- 캔버스에 `touch-action: none`, body에 `overscroll-behavior: none`을 적용했습니다.
- 선택 후 항상 보이는 편집·삭제 toolbar를 유지했습니다.
- 편집 대화상자 입력을 16px로 설정해 focus 시 자동 확대를 줄였습니다.
- 전역 `:focus-visible` ring과 `aria-label`을 보완했습니다.
- 팔레트 기호에 `단말`, `입출력`, `처리`, `판단` 이름을 표시했습니다.

### 문법 도움말과 예제 화면

- [`src/components/SyntaxHelp.tsx`](../../src/components/SyntaxHelp.tsx)에 접이식 문법 도움말을 추가했습니다.
- 도움말 본문은 편집기 위에 겹쳐 표시해 화면 전체 높이를 늘리지 않습니다.
- 바깥을 누르거나 `Esc`를 누르면 닫힙니다.
- 예제를 `#/examples` 화면으로 분리했습니다.
- 편집 화면을 unmount하지 않고 감춰 예제 화면을 왕복해도 작업 상태가 유지됩니다.
- 예제 미리보기는 저장용 SVG 생성기를 재사용합니다.

### 기호 모양 교정

- 평행사변형과 마름모를 CSS `clip-path` 대신 SVG `polygon`으로 바꿨습니다.
- 비스듬한 모든 변에 윤곽선이 남도록 했습니다.
- 판단 팔레트 기호를 육각형이 아닌 마름모로 바로잡았습니다.
- 화면, 팔레트, PNG가 같은 교육 표기 규칙을 따르도록 맞췄습니다.

현재 기준은 [순서도 기호 규칙](../flowchart-symbols.md)에 정리되어 있습니다.

### 화살표 가독성 수정

연결점 상자 자체를 44×44px로 키웠을 때 React Flow가 화살표 끝을 상자 바깥에 붙여, 86px 노드 간격의 선이 약 2px로 줄어드는 문제가 있었습니다.

- 실제 Handle은 16×16px로 되돌렸습니다.
- `::before`로 터치 영역만 44×44px까지 확장했습니다.
- 일반 화살표를 `#475569`, 2.2px로 진하게 조정했습니다.
- 반복 복귀선을 보라색으로 구분했습니다.
- React Flow marker에 색을 직접 지정해 선과 화살촉 색을 일치시켰습니다.
- 화면과 PNG의 선 굵기와 화살촉 크기를 함께 맞췄습니다.

### 판단 분기 교차 수정

이전에는 `예/아니오` 두 선이 마름모 바닥 부근에서 출발해 자동 배치 결과에 따라 서로 교차했습니다.

- 두 선을 마름모의 왼쪽·오른쪽 꼭짓점에서 출발시켰습니다.
- `decisionSides`가 목적지 위치를 비교해 다음 기호가 있는 쪽을 `예`로 정합니다.
- `yesSide`를 노드 Handle, 경로 계산, PNG 출력이 함께 사용하도록 했습니다.
- 빈 갈래는 그래프 바깥 lane으로 우회합니다.

### PNG 저장

화면 캡처 방식에서 React Flow 화살표가 잘리고 `예/아니오` 라벨이 깨지는 문제가 있어 그래프 기반 저장으로 교체했습니다.

- [`src/core/flowToSvg.ts`](../../src/core/flowToSvg.ts)가 노드와 화살표를 독립 SVG로 직렬화합니다.
- [`src/core/edgeGeometry.ts`](../../src/core/edgeGeometry.ts)의 경로 함수를 화면과 저장 이미지가 공유합니다.
- `graphBounds`가 노드뿐 아니라 반복 우회선까지 이미지 범위에 포함합니다.
- SVG를 canvas에 2배 크기로 그린 뒤 흰 배경 PNG로 저장합니다.
- 손잡이, 선택 표시와 편집 toolbar는 이미지에서 제외합니다.

### 안정적인 화면 맞추기

React Flow의 `fitView`가 감춰진 캔버스와 연속 예제 변경에서 오래된 DOM 크기를 사용해 viewport가 어긋나는 문제가 있었습니다.

- `graphBounds`로 알고 있는 그래프 좌표에서 viewport를 직접 계산합니다.
- 자동 맞춤 최대 zoom을 1로 제한해 노드가 적을 때 과도하게 확대하지 않습니다.
- `ResizeObserver`로 캔버스가 다시 보이는 시점을 감지합니다.
- React Flow가 viewport 요청을 반영할 때까지 animation frame에서 제한적으로 재시도합니다.

## 선택 이유와 고려한 대안

### 디자인 token을 먼저 모은 이유

색과 간격을 컴포넌트별 literal로 두면 화면을 다듬을 때 같은 의미의 값이 조금씩 달라지고, 순서도 표준색처럼 바꾸면 안 되는 값도 찾기 어렵습니다. CSS custom properties로 역할을 이름 붙여 일반 UI 색과 교육 기호 색을 구분했습니다. 다크 모드는 아직 구현하지 않았지만 token 구조 덕분에 이후 theme을 추가할 위치도 명확합니다.

### 좁은 화면용 별도 UI를 만들지 않은 이유

이 프로젝트의 수업 환경은 데스크톱과 가로형 크롬북입니다. 휴대폰 대응을 위해 의사코드와 순서도를 tab으로 분리하면 두 표현을 동시에 비교한다는 핵심 학습 경험이 사라지고, 대상이 아닌 환경 때문에 기준 화면의 복잡도가 커집니다. 대신 터치 입력은 그대로 지원해 터치 크롬북에서 사용할 수 있게 했습니다.

### 도움말을 overlay로 연 이유

접이식 내용을 일반 문서 흐름에 넣으면 펼칠 때 편집기와 캔버스가 아래로 밀리고 1366×768에서 body scroll이 생깁니다. overlay는 작업 공간의 높이를 유지하지만 편집기를 가릴 수 있으므로 바깥 pointer와 `Esc`로 즉시 닫히게 했습니다.

### 예제 화면을 분리하되 편집 화면을 유지한 이유

예제를 편집 화면 안에 상시 노출하면 제한된 세로 공간을 차지합니다. 별도 hash route는 주소 공유와 뒤로가기를 제공하지만 편집 화면을 unmount하면 그리던 React Flow 상태가 사라집니다. 따라서 route를 나누고 기존 편집 DOM은 `hidden`으로만 감췄습니다.

### 화면 캡처 대신 SVG를 직접 만든 이유

검토한 `html-to-image` 방식은 React Flow가 edge마다 만드는 크기 없는 내부 SVG와 `overflow: visible` 경로를 제대로 포함하지 못했습니다. 화살표가 빠지고 분기 label 배경이 깨지는 결과가 나왔습니다. 이미 노드 좌표, 크기와 `routePoints`를 갖고 있으므로 독립 SVG를 만드는 편이 deterministic하고 외부 capture 의존성도 줄일 수 있었습니다.

### 연결점의 시각 크기와 터치 영역을 분리한 이유

44px 접근성 기준을 Handle box 자체에 적용하면 React Flow의 edge anchor도 그 box 바깥으로 이동합니다. 사용자에게 필요한 것은 44px hit area이지 44px anchor geometry가 아니므로, 작은 Handle을 유지하고 pseudo-element만 넓혀 두 요구를 분리했습니다.

### `예` 방향을 고정하지 않은 이유

항상 왼쪽을 `예`로 정하면 dagre가 실제 `예` 본문을 오른쪽에 배치했을 때 두 branch가 마름모 바로 아래에서 교차합니다. 배치가 끝난 뒤 목적지 위치를 보고 `예` 방향을 정하면 의미를 바꾸지 않으면서 선 교차를 줄일 수 있습니다.

### `fitView` 대신 bounds를 직접 계산한 이유

`fitView`는 React Flow가 DOM에서 측정한 최신 크기에 의존합니다. 감춰진 화면이 다시 보이거나 예제를 빠르게 바꾸는 동안에는 측정 시점이 늦어 잘못된 zoom이 남았습니다. 자동 배치와 export가 이미 사용하는 `graphBounds`를 viewport에도 재사용하면 노드와 우회선까지 같은 기준으로 맞출 수 있습니다.

### 실행 애니메이션을 제외한 이유

현재 조건과 식은 자유로운 한국어 문자열입니다. 한 단계씩 실행하려면 값 type, 입력 방식, 연산 우선순위, 조건 평가와 오류 규칙을 갖춘 별도 언어가 필요합니다. 표현 학습 도구의 범위를 넘어서는 작업이므로 불완전한 evaluator를 붙이지 않고 명시적으로 제외했습니다.

## 완료 기준

- 1366×768과 1440×900 viewport에서 편집 화면 전체가 들어갑니다.
- 44×44px 조작 영역, focus 표시와 대체 편집 버튼을 제공합니다.
- 팔레트, 캔버스와 PNG의 기호 모양이 일치합니다.
- 일반·분기·반복 화살표가 읽기 쉽고 다른 기호를 불필요하게 통과하지 않습니다.
- 예제 화면과 편집 화면을 왕복해도 작업이 유지됩니다.
- 순서도를 우회선과 라벨이 잘리지 않는 PNG로 저장할 수 있습니다.
- 자동 화면 맞춤이 예제 변경과 화면 재표시 후에도 안정적으로 동작합니다.

## 검증 결과와 남은 작업

브라우저의 1366×768과 1440×900 viewport에서 다음 항목을 확인했습니다.

- 세로 스크롤 없는 전체 레이아웃
- 의사코드→순서도와 순서도→의사코드
- 예제 화면 왕복과 브라우저 뒤로가기
- 팔레트 탭 추가, 노드 편집, 미완성 연결 안내
- PNG 저장과 콘솔 오류 여부

실제 터치 크롬북에서는 다음 항목을 추가로 확인해야 합니다.

- 두 손가락 핀치와 한 손가락 캔버스 이동
- 팔레트 드래그의 실제 조작감
- 노드 더블탭 편집
- 화면 키보드가 올라왔을 때의 가림 여부

실기기 점검표는 [UI와 터치 입력](../ui-touch.md#수동-터치-점검표)을 참고합니다.
