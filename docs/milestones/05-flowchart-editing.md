# 5단계 — 순서도 직접 편집

> 상태: 완료

## 목표

학생이 마우스와 터치로 순서도 기호를 추가·편집·연결하고, 완성된 그래프를 `Program` AST와 의사코드로 되돌릴 수 있게 합니다.

## 구현 내용

### 팔레트와 기호 추가

[`src/components/Palette.tsx`](../../src/components/Palette.tsx)에 단말, 입출력, 처리, 판단 기호를 제공했습니다.

- HTML5 Drag and Drop API 대신 Pointer Events를 사용합니다.
- 마우스나 손가락으로 기호를 캔버스에 끌어 놓을 수 있습니다.
- 기호를 탭해 선택한 다음 캔버스 위치를 탭할 수도 있습니다.
- 7px 이상 움직였을 때 드래그로 판단하고 손끝 위치에 미리보기를 표시합니다.
- 시작이 있고 끝이 없을 때 새 단말 기호는 끝 역할을 합니다.

이 단계에서 만든 팔레트는 6단계에서 기호 이름과 최종 SVG 모양을 추가해 보완했습니다.

### 노드와 연결 편집

[`src/components/FlowCanvas.tsx`](../../src/components/FlowCanvas.tsx)에 직접 편집 기능을 구현했습니다.

- 노드를 드래그해 위치를 바꿉니다.
- 연결점 사이를 이어 화살표를 만듭니다.
- 노드를 더블클릭·더블탭하거나 선택 후 `편집` 버튼을 누릅니다.
- 선택한 노드와 엣지에 삭제 toolbar를 표시합니다.
- 노드 편집 대화상자에서 대입식, 입출력 값, 조건식과 판단 종류를 수정합니다.
- `←`, `×`, `÷` 기호 버튼을 제공합니다.
- 판단 종류를 조건에서 반복으로 바꾸면 기존 합류점을 제거하고, 반복에서 조건으로 바꾸면 합류점을 추가합니다.

연결 단계에서 다음 잘못된 연결을 미리 제한합니다.

- 자기 자신으로 연결
- 끝 기호에서 나가는 연결
- 시작 기호로 들어오는 연결
- 같은 source Handle에서 두 번 나가는 연결
- 일반 노드에 둘 이상의 화살표가 들어오는 연결

반복 판단과 합류점은 구조상 최대 두 개의 들어오는 화살표를 허용합니다.

### 그래프 → AST

[`src/core/flowToAst.ts`](../../src/core/flowToAst.ts)가 그래프 구조를 검증하면서 AST로 복원합니다.

- 시작과 끝 기호 수, 연결 방향을 확인합니다.
- 시작에서 모든 기호에 도달할 수 있는지 확인합니다.
- 처리·입력·출력 라벨을 AST 문장으로 변환합니다.
- 일반 문장의 나가는 화살표가 하나인지 확인합니다.
- 판단에 `예`와 `아니오`가 하나씩 있는지 확인합니다.
- 반복의 `예` 흐름이 같은 판단으로 돌아오는지 확인합니다.
- 조건의 두 흐름이 같은 합류점에서 만나는지 확인합니다.
- 중복 ID, 잘못된 순환, 사용되지 않은 기호를 거부합니다.

시작 기호 하나만 있고 엣지가 없는 그래프는 빈 프로그램으로 허용합니다.

### 미완성 그래프 처리

순서도를 만드는 중에는 끝 기호나 화살표가 빠질 수 있습니다. 이 상태를 삭제하거나 이전 AST로 되돌리지 않습니다.

- 현재 그래프를 그대로 유지합니다.
- `FlowValidationError`의 한국어 메시지를 의사코드 영역에 표시합니다.
- 끝 기호 추가, 시작 연결, 끊긴 기호 연결처럼 다음 행동을 구체적으로 안내합니다.
- 그래프가 유효해지는 순간 AST와 의사코드를 다시 갱신합니다.

## 선택 이유와 고려한 대안

### Pointer Events를 사용한 이유

HTML5 Drag and Drop API는 mouse 중심이며 터치스크린에서 일관되게 동작하지 않습니다. mouse event와 touch event를 별도로 구현하면 같은 gesture 상태를 두 벌 관리해야 합니다. Pointer Events는 마우스, 손가락과 pen을 하나의 흐름으로 다루고 pointer capture도 제공하므로 팔레트 drag의 공통 기반으로 선택했습니다.

### 탭하여 추가를 함께 제공한 이유

터치에서 긴 거리를 drag하거나 작은 캔버스 위치에 정확히 drop하는 작업은 학생에게 부담이 될 수 있습니다. drag를 제거하면 mouse 사용성이 떨어지므로 두 방식을 경쟁시키지 않고 함께 제공합니다. 탭 방식은 기호 선택과 위치 선택을 두 단계로 나누어 정확도를 높입니다.

### hover와 더블클릭에만 의존하지 않은 이유

터치에는 hover가 없고 더블탭은 브라우저 확대 gesture와 충돌할 수 있습니다. 빠른 mouse 작업을 위해 더블클릭은 유지하되, 노드를 한 번 선택하면 편집·삭제 버튼이 항상 나타나는 경로를 동등하게 제공합니다.

### 잘못된 연결을 즉시 차단하고 전체 구조도 다시 검증하는 이유

끝에서 나가는 선이나 같은 Handle의 중복 연결처럼 명백한 오류는 연결 시점에 막는 편이 이해하기 쉽습니다. 하지만 중첩 분기의 합류와 반복 순환처럼 전체 그래프를 봐야 아는 오류까지 UI callback에서 모두 판단하면 규칙이 분산됩니다. 그래서 `isValidConnection`은 지역 규칙만 빠르게 검사하고, `flowToAst`가 전체 구조를 최종 검증합니다.

### 미완성 그래프를 보존하는 이유

기호를 하나 놓은 직후나 화살표를 옮기는 동안 그래프는 자연스럽게 불완전합니다. 매 순간 구조를 강제하거나 마지막 유효 그래프로 되돌리면 자유 편집이 사실상 불가능해집니다. 그래프 상태와 유효한 AST를 분리해 작업 중인 모양은 보존하고, 변환할 수 없는 이유만 의사코드 영역에 표시합니다.

### 구조를 제한하는 이유

완전히 자유로운 directed graph는 하나의 중첩된 `Program` AST로 항상 표현할 수 없습니다. 임의의 합류, 여러 진입점과 비구조적 cycle을 허용하면 생성할 의사코드의 블록 범위가 모호해집니다. 시작·끝, 단일 다음 흐름, 명시적 합류점과 반복 cycle이라는 구조를 검증해 양방향 변환 가능성을 보장합니다.

## 완료 기준

- 마우스와 터치로 기호를 추가할 수 있습니다.
- 노드 내용과 판단 종류를 편집할 수 있습니다.
- 노드와 엣지를 연결·삭제할 수 있습니다.
- 올바른 순서도를 AST와 의사코드로 복원할 수 있습니다.
- 미완성 그래프를 유지하면서 해결 방법을 안내합니다.
- 중첩 반복과 조건 분기도 왕복 변환할 수 있습니다.

## 다음 단계로 전달한 규칙

- 터치에서 사용할 수 없는 호버 전용 조작을 만들지 않습니다.
- 그래프 편집 결과가 유효할 때만 AST를 교체합니다.
- 구조 오류는 내부 용어 대신 다음 행동으로 안내합니다.
- 화면의 연결점 위치와 자동 경로 계산이 일치해야 합니다.
