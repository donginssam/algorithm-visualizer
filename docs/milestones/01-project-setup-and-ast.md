# 1단계 — 프로젝트 설정과 AST

> 상태: 완료

## 목표

양방향 변환의 중심이 되는 타입과 최소 실행 환경을 먼저 만들고, 이후 단계에서 사용할 예제 알고리즘을 AST로 표현합니다.

## 구현 내용

### 프로젝트 기반

- React 18, TypeScript, Vite 기반 프로젝트를 구성했습니다.
- 개발 서버, TypeScript 검사, 배포 빌드와 Vitest를 실행할 수 있도록 `package.json` script를 정의했습니다.
- 브라우저 진입점과 전역 CSS 구조를 만들었습니다.

### AST 정의

[`src/core/ast.ts`](../../src/core/ast.ts)에 다음 문장 타입을 정의했습니다.

- `AssignNode`: 변수 대입과 계산
- `InputNode`: 값 입력
- `OutputNode`: 값 출력
- `LoopNode`: 조건과 반복 본문
- `IfNode`: 조건, `예` 본문, `아니오` 본문
- `Statement`: 위 노드들의 discriminated union
- `Program`: 최상위 `Statement[]`

`시작`과 `끝`은 AST 노드로 저장하지 않고 `Program`의 경계에 암묵적으로 포함했습니다. 조건과 계산식은 실행하지 않고 문자열 그대로 보존하도록 결정했습니다.

전체 타입 정의와 필드 의미는 [의사코드와 AST](../pseudocode.md#ast-노드-타입)를 참고합니다.

### 예제 데이터

[`src/examples/index.ts`](../../src/examples/index.ts)에 두 예제를 AST로 작성했습니다.

- 제곱의 합 구하기: 대입, 반복, 출력 사용
- 짝수 판별하기: 입력, 조건 분기, 출력 사용

두 예제는 이후 AST→순서도, AST→의사코드, 예제 화면을 개발할 때 공통 검증 데이터로 사용했습니다.

### 초기 확인 화면

초기에는 AST 구조를 직접 확인하는 임시 화면을 사용했습니다. 이 화면은 2단계의 순서도 캔버스와 이후의 최종 편집 화면으로 교체됐으므로 현재 코드에는 남아 있지 않습니다.

## 선택 이유와 고려한 대안

### 의사코드와 그래프 사이에 AST를 둔 이유

의사코드 텍스트를 분석해 곧바로 React Flow 노드를 만들거나, 그래프를 직접 의사코드 문자열로 바꾸는 방식도 가능했습니다. 하지만 두 변환이 서로 다른 규칙을 갖게 되면 한쪽에서 지원한 중첩 구조를 반대쪽에서 잃기 쉽고, UI 상태까지 변환 로직에 섞이게 됩니다.

AST를 단일 중간 표현으로 두면 다음 이점이 있습니다.

- 의사코드와 순서도 변환을 각각 AST 기준으로 나눌 수 있습니다.
- React와 DOM 없이 `src/core/`의 순수 함수만 테스트할 수 있습니다.
- `parse(generate(ast)) === ast`와 그래프 왕복 같은 불변식을 검증할 수 있습니다.
- 예제도 화면 데이터가 아니라 알고리즘 데이터로 재사용할 수 있습니다.

대신 새 문장 타입을 추가할 때 파서, 생성기, 그래프 변환 양쪽을 모두 수정해야 합니다. 이 비용은 두 표현의 일관성을 강제하는 의도적인 제약입니다.

### 시작과 끝을 AST 노드로 두지 않은 이유

시작과 끝은 모든 프로그램의 문장이라기보다 표현의 경계입니다. AST에 넣으면 중첩 블록에도 단말 노드가 들어갈 가능성이 생기고, `Program.body`를 순회할 때 실제 실행 문장과 경계 표시를 계속 구분해야 합니다. 따라서 AST에는 본문만 저장하고 텍스트·그래프 변환기가 경계를 책임지게 했습니다.

### 식을 별도 문법으로 해석하지 않은 이유

중학생이 쓰는 `수가 5보다 작거나 같을 때까지` 같은 표현을 실행 가능한 식으로 만들려면 변수, 연산자, 타입과 한국어 표현의 범위를 새로 정의해야 합니다. 현재 목표는 알고리즘의 표현 학습이므로 조건과 계산식은 문자열로 보존했습니다. 실행 기능은 단순한 후속 UI가 아니라 별도의 언어 설계 작업으로 남겨 둡니다.

### 예제를 AST로 작성한 이유

예제를 의사코드 문자열로 저장하면 화면을 열 때마다 파싱해야 하고, 문법 오류가 섞이면 앱의 기본 데이터가 깨집니다. AST로 작성하면 TypeScript가 문장 형태를 검사하고, 순서도와 의사코드 양쪽에서 같은 예제를 사용할 수 있습니다.

## 주요 산출물

| 파일                    | 역할                                       |
| ----------------------- | ------------------------------------------ |
| `package.json`          | 의존성과 실행 명령                         |
| `src/main.tsx`          | React 애플리케이션 진입점                  |
| `src/core/ast.ts`       | 공통 AST 타입                              |
| `src/examples/index.ts` | 학습·검증용 예제 AST                       |
| `src/App.tsx`           | 당시 임시 확인 화면, 현재는 최종 화면 조립 |

## 완료 기준

- 프로젝트가 개발 서버와 TypeScript 환경에서 실행됩니다.
- 모든 지원 문장을 AST로 표현할 수 있습니다.
- 반복과 조건을 중첩할 수 있습니다.
- 예제 두 개를 AST 데이터만으로 정의할 수 있습니다.
- UI와 무관한 공통 모델이 `src/core/`에 위치합니다.

## 다음 단계로 전달한 규칙

- 의사코드와 순서도는 반드시 `Program` AST를 거칩니다.
- 식과 조건은 문자열로 보존합니다.
- 시작·끝 표현은 변환기가 자동으로 담당합니다.
- 새 문장 타입은 이후 양방향 변환을 모두 구현해야 합니다.
