# 4단계 — 의사코드 생성기

> 상태: 완료

## 목표

`Program` AST를 다시 편집 가능한 표준 의사코드로 만들고, 파서와 생성기가 정보를 잃지 않고 왕복하는지 자동 테스트로 검증합니다.

## 구현 내용

### AST → 의사코드

[`src/core/astToText.ts`](../../src/core/astToText.ts)의 `astToText`가 AST를 줄 목록으로 변환합니다.

- 대입은 `변수 ← 식`으로 출력합니다.
- 입력과 출력은 `입력: 변수`, `출력: 식`의 접두형으로 통일합니다.
- 반복은 `[${condition} 반복]` 뒤에 본문을 공백 2칸 더 들여씁니다.
- 조건은 `[만약 ${condition}]` 뒤에 `thenBody`를 출력합니다.
- `elseBody`가 비어 있지 않을 때만 `[아니면]`과 본문을 출력합니다.
- 중첩 깊이마다 공백 2칸을 추가합니다.

파서는 접두형과 접미형 입력·출력을 모두 읽지만 생성기는 접두형 하나만 사용합니다. 여러 입력을 허용하면서도 저장·표시 결과는 일관되게 유지하기 위한 결정입니다.

### 빈 프로그램

본문이 없는 `{ body: [] }`은 `시작` 한 줄로 출력합니다. 본문이 하나라도 있으면 `시작`, 본문, `끝` 순서로 출력합니다.

이 규칙은 초기 순서도가 시작 기호 하나만 가지는 규칙과 맞물립니다. 빈 프로그램을 `시작\n끝`으로 생성하도록 바꾸면 AST→순서도와 그래프→AST의 예외 규칙도 함께 바꿔야 합니다.

### 왕복 테스트

[`src/core/parser.test.ts`](../../src/core/parser.test.ts)에서 다음 불변식을 검증합니다.

```typescript
parsePseudocode(astToText(program)) === program
```

대입, 입력, 출력뿐 아니라 중첩된 반복과 조건 분기를 포함한 AST를 사용해 문자열 변환 과정에서 정보가 사라지지 않는지 확인합니다.

### 상태 동기화

[`src/store/useAppStore.ts`](../../src/store/useAppStore.ts)가 유효한 `Program`을 의사코드로 바꿔 편집기에 전달합니다.

- 예제를 불러오면 AST에서 의사코드를 생성합니다.
- 순서도 편집이 유효한 AST를 만들면 의사코드를 다시 생성합니다.
- 의사코드 파싱에 실패하면 기존 유효 AST를 유지하고 초안과 오류만 표시합니다.

## 선택 이유와 고려한 대안

### 생성 결과를 한 가지 형식으로 제한한 이유

파서는 `입력: 수`와 `수 입력`처럼 학생이 사용할 수 있는 여러 형식을 받아들입니다. 생성기까지 원래 표기 방식을 기억하려면 AST에 표현 스타일 정보를 추가해야 하고, 같은 알고리즘이 불필요하게 여러 상태를 갖게 됩니다. AST에는 의미만 저장하고 생성기는 접두형 입출력과 공백 2칸 들여쓰기라는 canonical form을 사용합니다.

그 결과 순서도에서 만든 의사코드와 예제 의사코드가 항상 같은 모양을 가지며, diff와 테스트도 단순해집니다.

### 문자열 snapshot보다 왕복 테스트를 우선한 이유

특정 AST의 출력 문자열만 비교하면 생성 결과가 보기에는 맞지만 다시 파싱할 때 의미가 달라지는 문제를 놓칠 수 있습니다. `parse(generate(ast)) === ast`는 파서와 생성기의 실제 계약을 검증합니다. 표준 문자열 snapshot도 유용하지만 양방향 일관성의 핵심 안전장치는 왕복 불변식입니다.

### 재귀 생성 방식을 사용한 이유

AST 자체가 반복과 조건 안에 `Statement[]`를 재귀적으로 가지므로, 현재 깊이를 인자로 받아 문장을 줄 목록으로 만드는 방식이 구조와 직접 대응합니다. 별도 visitor framework를 도입할 만큼 노드 종류가 많지 않아 간단한 exhaustive `switch`를 사용했고, TypeScript가 새 union member의 누락을 드러내도록 했습니다.

### 빈 프로그램에서 끝을 생략한 이유

처음부터 `시작 → 끝`을 만들면 학생이 첫 기호를 넣기 위해 기존 연결을 끊어야 합니다. `시작` 하나를 유효한 빈 프로그램으로 정의하면 텍스트와 그래프 모두 같은 미완성 출발점을 가집니다. 문장이 추가되는 순간 `끝`을 요구해 완성 조건도 명확하게 유지합니다.

| `src/core/astToText.ts` | AST→표준 의사코드 생성 |

## 완료 기준

- 모든 AST 문장 타입을 표준 의사코드로 출력할 수 있습니다.
- 들여쓰기가 중첩 깊이와 일치합니다.
- `[아니면]`이 필요한 경우에만 출력됩니다.
- 빈 프로그램이 `시작` 한 줄로 출력됩니다.
- 생성한 의사코드를 다시 파싱하면 원래 AST와 같습니다.

## 다음 단계로 전달한 규칙

- AST가 유효한 두 표현 사이의 유일한 중간 표현입니다.
- 생성기는 언제나 일관된 표준 형식을 사용합니다.
- 새 AST 노드는 파서, 생성기와 왕복 테스트를 함께 추가해야 합니다.
- 순서도 편집 결과도 같은 생성기를 거쳐 의사코드가 됩니다.
