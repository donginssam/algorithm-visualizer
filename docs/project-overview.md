# 프로젝트 개요와 기술 결정

## 프로젝트 목적

`알고리즘 표현하기`는 중학교 정보 교과의 알고리즘 단원을 위한 웹 기반 학습 도구입니다. 학생이 같은 알고리즘을 의사코드와 순서도로 번갈아 표현하면서 두 표현의 관계를 이해하는 것이 목표입니다.

핵심 기능은 다음 세 가지입니다.

1. 의사코드를 입력하면 순서도를 자동으로 만듭니다.
2. 순서도를 직접 편집하면 의사코드를 자동으로 만듭니다.
3. 완성한 순서도를 과제 제출용 PNG로 저장합니다.

의사코드와 순서도 중 한쪽만 만드는 도구가 아니라, **순서도 ↔ 의사코드 양방향 변환**이 제품과 아키텍처의 중심입니다.

## 대상 환경과 화면 제약

- 주 사용자는 중학생과 수업을 진행하는 교사입니다.
- 대상 기기는 데스크톱과 가로형 크롬북입니다.
- 기준 viewport는 크롬북에서 흔한 1366×768입니다.
- 편집 화면 전체가 기준 viewport에 세로 스크롤 없이 들어가야 합니다.
- 터치스크린 크롬북을 고려해 마우스와 터치를 동급 입력 수단으로 지원합니다.
- 휴대폰과 태블릿 세로 모드용 별도 레이아웃은 지원 범위가 아닙니다.

화면과 터치 입력의 상세 규칙은 [UI와 터치 입력](./ui-touch.md)을 참고합니다.

## 기능 요구사항

### 의사코드 편집

- 공백 2칸 들여쓰기를 사용하는 교육용 문법을 제공합니다.
- 대입, 입력, 출력, 반복, 조건 분기를 지원합니다.
- `<-`와 `*`를 각각 `←`와 `×`로 자동 변환합니다.
- 오류가 발생한 줄과 고치는 방법을 쉬운 한국어로 안내합니다.
- 입력 후 약 300ms 뒤 순서도를 갱신합니다.

### 순서도 편집

- 단말, 입출력, 처리, 판단 기호를 팔레트에서 추가합니다.
- 기호를 드래그하거나 탭한 뒤 캔버스를 탭해 추가할 수 있습니다.
- 기호의 내용, 위치, 연결을 직접 편집할 수 있습니다.
- 미완성 그래프를 버리지 않고 다음에 필요한 연결이나 기호를 안내합니다.
- 올바른 구조가 완성되면 의사코드를 자동으로 갱신합니다.

### 학습 편의 기능

- 문법 도움말과 예제 알고리즘을 제공합니다.
- 순서도를 2배 해상도의 PNG로 저장합니다.
- 확대·축소, 화면 맞춤, 키보드 focus 표시를 제공합니다.

## 기술 스택과 선택 이유

| 영역        | 기술                         | 선택 이유                                                     |
| ----------- | ---------------------------- | ------------------------------------------------------------- |
| UI          | React 18, TypeScript, Vite   | 컴포넌트 기반 UI, 정적 타입, 빠른 개발·빌드 환경              |
| 순서도      | React Flow (`@xyflow/react`) | 커스텀 노드, 연결 편집, 이동·확대·터치 제스처 지원            |
| 자동 배치   | dagre                        | 구조화된 그래프를 위→아래 순서도로 배치하기 적합              |
| 코드 편집   | CodeMirror 6                 | 한글 입력, diagnostic, 기호 자동 변환을 확장하기 쉬움         |
| 상태 관리   | zustand                      | AST 하나를 중심으로 한 작은 전역 상태에 적합                  |
| 테스트      | Vitest                       | TypeScript 변환 로직과 Vite 환경을 빠르게 검증                |
| 이미지 저장 | 자체 SVG 직렬화 + canvas     | 화면 캡처의 SVG 잘림 문제 없이 항상 같은 결과 생성            |
| 화면 전환   | URL hash + `hashchange`      | 화면이 두 개뿐이며 별도 router 없이 뒤로가기와 링크 공유 가능 |
| 스타일      | CSS custom properties        | 색, 간격, 터치 크기 등 결합된 값을 한곳에서 관리              |

## 핵심 기술 결정

### AST를 단일 중간 표현으로 사용

의사코드 텍스트와 순서도 그래프를 서로 직접 수정하지 않습니다. 두 표현을 모두 `Program` AST로 변환하고 AST에서 반대쪽 표현을 다시 만듭니다. 이 방식은 양방향 일관성과 왕복 테스트를 가능하게 합니다.

자세한 데이터 흐름은 [아키텍처](./architecture.md), 문법과 타입은 [의사코드와 AST](./pseudocode.md)를 참고합니다.

### 조건식은 문자열 그대로 보존

`수가 5보다 작거나 같을 때까지` 같은 한국어 조건을 실행 가능한 식으로 해석하지 않습니다. 조건식과 계산식은 입력한 문자열을 보존하고 화면에 표시하는 데만 사용합니다. 덕분에 학생이 자연스러운 표현을 쓸 수 있지만, 현재 범위에서는 알고리즘 실행 애니메이션을 제공하지 않습니다.

### 자유 편집 그래프는 검증 후 AST로 변환

학생이 순서도를 만드는 중에는 끝 기호나 연결이 빠질 수 있습니다. 미완성 그래프를 강제로 고치거나 삭제하지 않고 유지하며, `flowToAst`가 구조를 검증해 다음 행동을 안내합니다. 조건 분기는 합류점에서 만나야 하고 반복만 판단 기호로 되돌아갈 수 있습니다.

상세 규칙은 [순서도 변환과 렌더링](./flowchart.md)을 참고합니다.

### 빈 프로그램은 `시작` 하나로 표현

처음부터 `시작 → 끝`을 보여 주면 완성된 프로그램처럼 보이고 기호를 넣으려면 기존 화살표를 먼저 지워야 합니다. 따라서 본문이 비어 있을 때는 의사코드 `시작` 한 줄과 순서도 시작 기호 하나만 보여 줍니다. 본문을 추가한 뒤에는 `끝`이 필수입니다.

### Pointer Events로 팔레트 조작

HTML5 Drag and Drop API는 터치에서 일관되게 동작하지 않으므로 사용하지 않습니다. Pointer Events 기반 드래그와 `기호 탭 → 캔버스 탭` 방식을 함께 제공합니다.

### SVG로 도형과 저장 이미지 생성

평행사변형과 마름모는 `clip-path`가 아니라 SVG `polygon`으로 그려 모든 변의 테두리를 유지합니다. PNG도 화면을 캡처하지 않고 그래프 좌표에서 독립 SVG를 생성한 뒤 canvas에 그립니다. 화면과 이미지가 화살표 경로 계산을 공유하므로 저장 결과가 UI 상태에 좌우되지 않습니다.

## 구현 현황

현재 다음 범위가 구현되어 있습니다.

- AST 타입과 예제 데이터
- AST→순서도 변환, dagre 자동 배치, 분기·반복 경로
- 의사코드 파서와 CodeMirror 편집기
- AST→의사코드 생성기와 왕복 테스트
- 마우스·터치 기반 순서도 추가, 편집, 연결, 삭제
- 순서도→AST 구조 검증과 한국어 안내
- 예제 화면, 문법 도움말, PNG 저장
- 1366×768과 1440×900 viewport 기준 레이아웃 점검

단계별 목표와 실제 구현 내용은 [구현 단계 기록](./milestones/README.md)에 정리되어 있습니다.

## 현재 제외한 범위

- 알고리즘 한 단계씩 실행하기
- 다크 모드
- `localStorage` 작업 자동 저장

제외 범위를 추가할 때는 단순히 UI를 붙이기보다 기존 AST, 양방향 변환, 터치 제약과 충돌하는지 먼저 검토합니다.

## 남은 확인과 개선 방향

우선순위가 높은 후속 작업은 다음과 같습니다.

1. 실제 터치 크롬북에서 핀치 확대, 캔버스 이동, 팔레트 드래그, 노드 더블탭, 화면 키보드를 점검합니다.
2. 실제 수업에서 사용한 뒤 예제, 오류 메시지, 조작 안내를 다듬습니다.
3. 기호가 많은 알고리즘에서 자동 배치와 반복 lane을 점검합니다.

검증 절차와 상세 점검표는 [테스트와 유지보수](./testing.md)에 있습니다.
